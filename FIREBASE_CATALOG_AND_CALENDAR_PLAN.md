# Бриф доработки Бухлографа: стабильный ассортимент, модерация и чистый UI

## Цель

Стабилизировать ассортимент, убрать технические детали из интерфейса, добавить пользовательские заявки на напитки через Realtime Database, дать админу удобную премодерацию, улучшить экран аккаунта, друзей, карту и маскота.

## 1. Ассортимент

- Убрать внешний импорт из основного сценария ассортимента.
- Основной источник подтвержденных напитков: Firestore `products`.
- Ассортимент не должен мигать: демо-напитки не должны появляться и исчезать из-за прав или пустого snapshot.
- На экране ассортимента должна быть кнопка `Добавить напиток`.
- Если пользователь админ, напиток добавляется сразу в `products`.
- Если пользователь обычный, напиток уходит на модерацию.
- В списке должны быть фильтры по тегам.

## 2. Добавление напитка

Поля напитка:

- название;
- бренд;
- описание;
- URL картинки;
- объем в мл;
- крепость в процентах;
- теги из фиксированного списка.

Пользователь не может писать свои теги. Он выбирает только из готовых:

- `#ПИВО`;
- `#ВИНО`;
- `#КРЕПКОЕ`;
- `#КОКТЕЙЛЬ`;
- `#ЛИКЕР`;
- `#СИДР`;
- `#СЛАБОЕ`;
- `#ДРУГОЕ`.

## 3. Админка

- У каждого профиля в Firestore должно быть поле `isAdmin: false`, если оно еще не создано.
- Чтобы выдать админку, достаточно вручную заменить `false` на `true`.
- Админ видит заявки пользователей в начале ассортимента.
- У заявки есть действия:
  - галочка: открыть окно премодерации;
  - крестик: отклонить;
  - скрыть автора: убрать заявки автора только из своего списка.
- При апруве открывается окно, где можно оставить данные как есть или поправить название, описание, картинку, градусы, объем, бренд и теги.
- После апрува напиток переносится в Firestore `products`, заявка помечается принятой.
- После отклонения заявка помечается отклоненной.

## 4. Realtime Database

Пользовательские заявки хранятся в Realtime Database, чтобы админ видел их сразу.

Структура:

```text
product_suggestions/{suggestionId}
  id
  product
  authorId
  authorName
  status
  createdAtMillis
  updatedAtMillis
```

Статусы:

```text
pending
approved
rejected
```

## 5. Добавление записи

- Убрать ползунки объема и крепости.
- Запись создается только по напитку из ассортимента.
- Объем и крепость берутся из карточки напитка.
- Оставить поле комментария.

## 6. Друзья

- Добавить кнопку удаления из друзей.
- Удаление должно убрать связь у текущего пользователя и у второго пользователя, если это возможно.

## 7. Чистый пользовательский интерфейс

Убрать технические фразы:

- `Firebase`;
- `Firestore`;
- `Realtime Database`;
- `FCM`;
- `snapshot`;
- `cache`.

Заменить на понятные тексты:

- `Ассортимент напитков`;
- `Заявка отправлена на модерацию`;
- `Данные синхронизированы`;
- `Не удалось загрузить данные`.

## 8. О нас и карта

- `О нас` больше не попап.
- Кнопка `i` во вкладке аккаунта открывает отдельное окно/панель поверх профиля.
- Внутри есть кнопка назад/закрыть.
- Адрес заменить на `Кемеровский государственный университет`.
- Маршрут строить до КемГУ.
- MapKit должен использовать нормальный lifecycle `MapView`.
- Если карта не загрузилась или нет ключа, показывать красивую заглушку без технических деталей.

## 9. Маскот

Заменить текстовые символы на emoji.

Добавить 12 состояний:

```text
0 мл        😭 пусто и драматично
1-4 мл      🥺 совсем чуть-чуть
5-14 мл     😐 почти академично
15-24 мл    🙂 культурный режим
25-34 мл    😎 график оживает
35-49 мл    😄 вечер пошел
50-64 мл    🥴 шумновато
65-79 мл    🤨 режим вопросов
80-94 мл    😵‍💫 опасная зона
95-114 мл   🤯 критично
115-139 мл  😡 режим совести
140+ мл     💀 завтра будет отчет
```

Эти состояния используются:

- на главном экране;
- в карточках друзей;
- в дневной статистике календаря.

## 11. Управление опубликованным ассортиментом

Админам нужно управлять уже опубликованными напитками в Firestore `products`.

- В карточке напитка админ видит действия `Изменить` и `Скрыть`/`Вернуть`.
- Редактирование открывает ту же форму, что добавление и премодерация.
- Админ может менять название, бренд, описание, картинку, объем, крепость, категорию и теги.
- Физическое удаление не используется, чтобы не ломать старые записи пользователей.
- Вместо удаления применяется мягкое скрытие:

```text
isActive: false
deletedAtMillis: timestamp
updatedBy: adminUid
```

- Обычные пользователи видят только активные напитки.
- Админ может фильтровать ассортимент: `Активные`, `Скрытые`, `Все`.
